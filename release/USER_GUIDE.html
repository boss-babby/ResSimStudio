Version: Round C27 (October 2026). This guide is updated with every release; the change log at the end lists what changed. Open it at any time from Help → User guide or with F1.

1.1 Finding your way (C26)

  • Start page (Help → Start page; shown at start-up unless you untick it in View → Settings → Interface): new demo or blank model, open / import, recent files, the built-in example library and the example decks shipped next to the program (examples\, decks\) with their description — one click opens a deck.
  • Command palette (Ctrl+Shift+P, or Ctrl+K outside the Deck Editor): every menu action, model section, example, example deck and recent file by name. Type a few letters (fuzzy search), Up / Down, Enter. Nothing has to be found in the menus.
  • Recent files: File → Recent (projects, decks, results), also on the start page and in the palette.
  • Workflow checklist (top of the Case Explorer): grid → fluids → rel. perm → initial state → wells → schedule → validate → run → results → save, each with its state (done / needs attention / results out of date); click a step to go there.
  • Notifications (bell in the status bar): every message with its time, errors marked — messages no longer disappear unseen.
  • Run history: every finished ResSim run is added to Results → Cases, vectors & compare with what changed against the previous run (input lines removed / added) — what-if comparisons without saving result files by hand. Switch off in View → Settings → Interface.

4. Tables — Excel-style editing (C15)

Every converted data table (layers, schedule, components, BIC, hydraulic fractures, stability planes ...) works like a spreadsheet:

  • Select: click a cell; Shift+click, Shift+arrows or drag for a block; click / drag the row numbers to select whole rows, click a column title to select the column (Shift+click extends to more columns); click "#" or press Ctrl+A to select all.
  • Copy / paste: Ctrl+C copies the selection as tab-separated text (pastes directly into Excel); Ctrl+V pastes text from Excel, LibreOffice, a web table or another table. If the clipboard block has the same size as the selection it is pasted exactly; a single value fills the whole selection; a larger block extends from the current cell (new rows are appended where the table allows it).
  • Edit: type to overwrite (F2 / Enter / double-click edits the current value), Tab moves on, Esc cancels, Delete clears (deletes the rows when whole rows are selected), Ctrl+D fills down, Ctrl+X cuts.
  • Right-click menu: Copy, Copy with headers, Cut, Paste, Replace the whole table with the clipboard, Fill down, Clear cells, Insert rows above / below, Delete selected rows, Select all.
  • Columns are resizable; values are never hidden behind narrow headers.
  • C16: the remaining tables use the same spreadsheet editor — aquifers (Fetkovich / Carter-Tracy), thermal components, solids, sorption, water-injection and trapping tables, EDFM fractures, mineral trapping, separator stages, MECHBC plates. Choice columns (e.g. aquifer type, phase) open a drop-down; computed columns are read-only (grey).
  • For developers: a new table is one RecordTable<T> declaration in widgets.h style — one line per column (.num, .integer, .text, .choice, .flag, .computed …) — and it gets selection, copy / paste, insert / delete and undo-safe change notification automatically.

Speed on one laptop / workstation (C21). On a single machine OpenMP threads are the fastest option: measured on a 54 000-cell case (2 cores) 1 thread 48.6 s → 2 threads 31.4 s, while 2-rank domain decomposition took 36.0 s (it adds ~40 % solver iterations because the ranks only exchange halo data). Recommendations: keep Threads at its default (one per physical core — hyper-threads slow the bandwidth-bound solver); use MPI DD only across several machines, or for memory; if you use DD on one machine, the panel sets ranks × threads ≤ physical cores and passive waiting (OMP_WAIT_POLICY=PASSIVE) automatically — without it idle ranks and threads spin and Task Manager shows ~100 % CPU without any speed-up. The GPU solver helps only on a discrete GPU with large models; a laptop iGPU is usually slower than the CPU (the AMG pressure stage still runs on the CPU). The HPC panel's Advisor line shows the recommended setting for the open model.

MPI troubleshooting (Intel MPI "error code 5 / Access is denied"). Press Test MPI; the log ends with a Diagnosis block. Usual fixes, in order: (1) right-click ResSimCLI.exe → Properties → Unblock (or copy the release folder out of Downloads, e.g. to C:\ResSim); (2) allow the folder in the antivirus / Controlled Folder Access; (3) Intel MPI older than 2021.6: put -localonly in Extra mpiexec arguments; (4) or install Microsoft MPI (msmpisetup.exe) and leave the mpiexec field empty. 5. Plots and export

Every plot has a small export icon (top-right corner while the mouse is over the plot): click it — or right-click the plot — to export that single plot as vector PDF or high-resolution PNG. Custom plots saves your own combinations of curves and shows them after every run. Logarithmic axes (e.g. rate vs time on log-log) are kept in the vector export with decade and minor ticks; long axis labels shrink to fit the figure height (C17).

7.1 Hydraulic fractures (HFRAC) — Grid & rock → Hydraulic fractures & unconventional

Each fracture is a vertical plane given by its trace (x0, y0) → (x1, y1), depth range, width, permeability, porosity, conductivity decline gamma and optional SATNUM. The grid cuts each plane into fracture cells (embedded discrete fracture model) connected to their host cells (T = 2 A k / ⟨d⟩), to each other along the plane and to every well perforated in a host cell. Works for Cartesian and corner-point grids, single and dual porosity, black-oil and compositional runs.

Multistage designer: choose the well, number of stages, spacing (0 = evenly along the completed length), orientation (perpendicular to the well, or along S_Hmax) and the geometry — either typed in, or sized from the pump schedule: rate, time, viscosity, E, ν, leak-off, toughness and closure stress run the PKN or KGD propagation model; the pumped proppant mass gives the propped width (w = M / (ρ_p (1−φ_p) 2 L_p H)). Replace or Append writes the table. The pre-check line shows how many fracture cells the grid preview created.

Deck lines (ResSim only):

-- RESSIM: HFRAC name x0 y0 x1 y1 zTop zBot width perm poro [gamma] [satnum]
--   zTop/zBot -1 = full grid thickness; perm 0 = cubic law w^2/12; width in length units
-- RESSIM: LANGMUIR VL PL rhoGrain      -- METRIC sm3/t, bar, g/cm3; FIELD scf/ton, psia, g/cm3
-- RESSIM: PERMSTRESS gamma             -- k = k0 exp(-gamma (p_i - p)), 1/pressure unit

Results: fracture panels in the 3D view coloured by the cell pressure / saturation, rates and cumulative production, adsorbed gas in the fluids-in-place.

Fracture growth during the run (C18) — open Fracture growth during the run (LEFM) below the fracture table (one row per fracture, Excel-style). Set K_IC > 0 and the fracture grows while the simulation runs: * the trace in the main table is the maximum length; at the start only the part within the initial half-length of the well is open (the closed rest behaves like the host rock); * after every time step the tip of each wing is tested: K_I = (p_fracture − σ_min) · √(π · min(L, H/2)); if K_I ≥ K_IC the next piece opens (one piece per wing per step); * σ_min is the minimum horizontal stress at the fracture mid-depth (+ gradient × depth difference); typical K_IC: shale 0.5–2, sandstone 0.5–1.5, granite 1–3 MPa·m^0.5; * the run log shows fracture F1 wing + grows to 65 m at t = 4.5 d (K_I 1.3 MPa m^0.5 >= K_IC 1); the Results 3D view has the cell array HFOPEN (1 = open); * what to expect: under injection the pressure climbs to about σ_min + K_IC/√(πH/2) and then stays there while the fracture grows (example: σ_min 340 bar, H 10 m → ≈ 342.5 bar); higher σ_min → slower growth; * limits: black-oil engine; straight vertical growth along the given trace; a piece = one host cell along the trace (refine the grid for smoother growth); adjoint HM is not available while fractures grow (use the ensemble / FD methods).

Deck line: -- RESSIM: HFGROW name K_IC sigmaMin [dSigma/dz] [initialHalfLength] [closedMultiplier] (after the HFRAC line of that fracture).

Verification (tests -hfbo): EDFM fracture vs Gringarten uniform-flux solution within 3.7 %; Langmuir material balance exact; corner-point = Cartesian to 1e-8.

Multi-cluster stage: stress shadowing & limited entry (C17) — in the designer tick Size from the pump schedule, then open Multi-cluster stage. Enter the clusters per stage, cluster spacing, perforations per cluster, perforation diameter, discharge coefficient (0.6 new, ≈ 0.9 eroded) and fluid density; the Perforation friction line shows the pressure drop at an even split. In the cluster table you can give each cluster a stress offset (MPa, e.g. a harder layer); the other columns are results. Simulate the stage grows all clusters together from one wellbore pressure: * every cluster opens against S_hmin + its offset + the stress shadow of the open neighbours (Sneddon crack) + its perforation friction; * the plots show each cluster's share of the pump rate over time and the final half-length per cluster; * typical result: with tight spacing the outer clusters take most of the fluid and the inner ones stay short; more perforation friction (fewer / smaller holes = limited entry) evens them out; * Use the mean cluster half-length for the stages writes the (propped) mean length into the stage design.

Example: 5 clusters, 10 m apart, 6 m³/min, 10 min — no shadow: 5 × 166 m; with shadow 240 / 96 / 110 / 96 / 240 m; with 4 × 10 mm perforations per cluster 170 / 165 / 164 / 165 / 170 m.

7.3 Steam producers: steam trap and steam-rate limit (C17)

Thermal → Steam injection → Producer steam trap and steam-rate limit (deck -- RESSIM: STEAMTRAP 'well' subcool [steamMax]). Subcool keeps the producer BHP at the saturation pressure of (hottest connection temperature + subcool), so live steam stays in the reservoir. Max steam (CWE volume per day) caps the produced steam: the well switches to a steam-rate control inside the Newton iterations whenever the limit would be exceeded and back when it is not (SPE4 2A: limit held in every report after breakthrough).

7.4 Diffusion and mechanical dispersion (compositional / CO2)

CO2 storage → Trapping & interactions → Solubility & diffusion, or Compositional → Diffusion & hysteresis → Diffusion for hydrocarbon runs. Molecular diffusion uses DIFFUSE + DIFFCWAT / DIFFCGAS / DIFFC. Since C17 mechanical dispersion can be switched on in the same tab: one dispersivity for all cells, or per-cell values from the deck array DISPERC (OPM Flow GRID keyword, length units). Mixing then grows with the flow velocity (flux = α |v| × concentration difference) — SPE11A uses 0.01 m, SPE11B/C 10 m. ECLIPSE has no DISPERC; OPM Flow reads it.

7.2 Geomechanics: fault & fracture stability — Tools → Geomechanics

The window opens as a tab next to the 3D Viewer (drag the tab out to float it, or double-click the tab bar to maximise). Inputs are on the left, results on the right.

  • Tip – no event? With the poroelastic stress path switched on, a pressure increase also raises S_h and S_H, which can stabilise a normal fault (the window says so and prints the final τ/σ'_n). Switch the stress path off to model localised injection close to the fault.
  • Stress state: depth, S_v / S_Hmax / S_hmin gradients, S_Hmax azimuth, pore-pressure gradient, Biot, ν, friction μ and cohesion; the faulting regime is shown.
  • Pore pressure: hydrostatic + change, or from the last ResSim run (field average, maximum cell, or one cell I, J, K) with the poroelastic stress path ΔS_h = ΔS_H = α(1−2ν)/(1−ν) Δp.
  • Planes: strike / dip table (filled from the hydraulic and thermal fractures plus the optimally oriented fault).
  • Outputs: effective normal and shear stress, slip tendency T_s = τ/σ'_n, dilation tendency, Coulomb failure stress CFF, critical pressure increase ΔP_crit and state (stable / critical / slipping); Mohr diagram (initial and current circles, Coulomb envelope, plane points), evolution of T and ΔP_ct with time, stereonet** (sl tendency of every orientation, lower hemisphere equal area), reservoir cells**bove the Coulomb line, and fracture movement: rate-and-state friction slip driven by the pressure history (stick-slip vs stable creep, events with slip, peak velocity, M_0 and M_w) with the Barton-Bandis aperture and the resulting permeability multiplier.

The 3D FEM of the thermal THM option (sagd_thm example) now has elasto-plasticity (C16) — Thermal editor → Geomechanics → Plasticity and damage:

  • Drucker-Prager yield surface matched to Mohr-Coulomb (outer cone, inner cone or plane strain), non-associated flow with a dilation angle, cohesion softening / hardening to a residual cohesion; implicit return mapping with Aitken-accelerated equilibrium iterations.
  • Damage permeability: k = k0 · exp(c · ε_p,vol) (capped), fed back into the flow every step — plastic dilation opens permeability.
  • Boundary conditions per face: fixed, traction, roller, or rigid plate (load- or displacement-controlled) for laboratory-style tests (-- RESSIM: MECHBC / GEOPLAST).
  • Results: equivalent plastic strain EPSPLAS, plastic volume strain EPSPV, permeability multiplier KDAMAGE in the 3D viewer and time plots.
  • Verified: platen test reaches the Mohr-Coulomb strength exactly (45.07 MPa), softening to the residual strength, Mandel and Cryer consolidation (< 0.3 % error).

7.5 Seismicity-aware injection design (C20) — Tools → Geomechanics: seismicity-aware injection design

Designs the injection-rate schedule that produces the fewest expected induced earthquakes for the volume you must inject, on the faults you mark.

  1. Fault patches: one row per fault cell (I, J, K) with friction, stress-path factor, Aσ̄ (MPa, typically 0.01–0.1), aftershock time t_a (years), background rate (1/yr) and a weight. dCFS = friction × stress-path factor × Δp.
  2. Designed injectors: the water / gas injectors of the case are listed with their volumes (Volume per well keeps each well's own volume, otherwise only the total is fixed).
  3. Schedule and objective: injection window and post-shut-in horizon (days) — count the post-shut-in events, otherwise step-up schedules look falsely good; control intervals and report steps; Max rate / mean rate; Objective (expected events, peak rate, or a mix with Peak weight); Model-correction passes.
  4. Design injection: the engine computes the stress response of every patch to every injector interval, the optimiser solves the (provably convex) minimum-seismicity problem, and the design is re-simulated; each correction pass removes the superposition error (Model correction tab: predicted vs simulated).
  5. Results (Injection schedule tab): the designed schedule vs constant rate (events, peak rate), Open designed case (a copy with the new schedule) and Copy SCHEDULE text.

If the log warns that the response is strongly nonlinear (for example a fracture that grows during injection, or BHP limits taking over), the designer relies on the verification runs and returns constant rate when nothing better was verified; reduce Max rate / mean rate.

Design potential and the shut-in burst (C22, research finding F12). After a design the panel shows Design potential (first-order reference): Π (maximum Coulomb change / Aσ̄ of the constant schedule), θ (stress response time / injection window) and the gain that the exact optimum would reach for a first-order (saturating) stress response — with and without a shut-in burst.

  • θ ≪ 0.1: the stress follows the rate — constant rate is already close to optimal, but rate spikes are expensive.
  • θ ≈ 0.1–1: the largest benefit from a designed schedule.
  • The reference is exact for first-order responses; radial / linear diffusive responses reach roughly ¼ to ¾ of it. The designed schedule is the real number; "at least" means θ is outside the validated range of the closed form.
  • The event-count optimum opens with a high-rate charging interval and tends to end with a burst at the rate limit just before shut-in. That lowers the count but raises the stress at shut-in, where large post-injection events are a known risk (Basel 2006, Pohang 2017). The panel warns when the design ends at its rate bound. Set Last-interval rate / mean to 1 (or lower) to forbid the burst; 0 = off.

Calibrate from observed stage events — does the rate matter? (C23, research finding F14). Below the designer: one row per stage of a past stimulation (test / interval number, injected volume, hydraulic energy ∫p q dt, mean rate, duration, located events). Fit kernels ranks the event-count kernels (constant, duration, volume, energy, volume × rate^β, volume × (1 + earlier volume)^γ and both together) by AIC with a separate productivity per test and reports the rate exponent β at fixed volume with its 95 % interval. If the interval contains 0, the data show no rate effect and a slower schedule will not reduce events by itself — only less volume (or energy) will. Aspo HF1 + HF2 example loads the Äspö HRL 2015 stages: best kernel volume × (1 + earlier volume)^0.45, β interval [−1.25, 0.75] → no resolvable rate effect.

Tips: the gain is largest when the fault is close to failure relative to Aσ̄ (strong nonlinearity); spreading the volume over several wells usually helps more than reshaping one well's rate. Black-oil cases only (compositional / thermal later).

7.6 Fracture contact & slip (embedded fractures, C20) — Tools → Geomechanics: fracture contact & slip (2-D)

A plane-strain mechanics section (width × height, rollers on the left and bottom, far-field stresses on the right and top; tension +, compression −) with any number of straight fractures that cut the mesh anywhere — no meshing along them.

  • Fractures table (Excel-style): end points, fluid pressure, friction coefficient, cohesion. Put end points on element edges for the most accurate tips; keep fractures at least one element apart.
  • Solve: the fractures open where the pressure exceeds the normal stress, stick where |τ| < c + μσ_n and slip otherwise (Coulomb friction, penalty contact, full Newton).
  • Results: Along the fractures — opening and slip (mm) and normal / shear contact traction (MPa) vs distance from the fracture centre; Stress map — σ_xx, σ_yy, σ_xy or maximum shear with the fractures drawn on top; the status line counts open / stick / slip elements.
  • Jump interpolation: Continuous jumps (default, accurate on any mesh) or Element-constant jumps (classic EFEM, kept for comparison: it over-predicts slip by 10–25 % on meshes oblique to the fracture).
  • Accuracy (built-in tests, 100 × 100 elements, crack ≈ 24 elements long): pressurised (Sneddon) crack volume within 2 %, frictional slip of an inclined crack within 5 %, locked crack correctly stays locked.

Example: default setup (a 30° fracture with μ = 0.3 under σ_yy = −10 MPa) → the fracture slips (tan 30° = 0.58 > 0.3). Set friction to 0.8 → no slip. Set friction 0, σ_yy = 0 and pressure 1 MPa → the Sneddon elliptical opening.

Coupled flow run (C21, G1-c). Open a model with HFRAC fractures (e.g. examples/HFGROW_INJECTION.DATA), set rock and far-field stresses at the top of this window (σ_yy acts across a fracture that runs along x), then under Coupled flow run with the open case choose the layer, the fracture friction and the Barton–Bandis closure parameters (residual aperture, maximum closure V_m, initial normal stiffness K_n0), the dilation angle and press Run coupled. After every report step the fracture pressures from the simulation load the fractures, the contact problem is solved and each fracture piece's conductance is set from its aperture: closed fractures stiffen as the effective normal stress grows, fractures above the normal stress open (width scaled to the fracture height, PKN), slipping fractures dilate. The Coupled flow run (G1-c) tab shows the aperture along the fractures, the conductance-multiplier range over time and the injector BHP (coupled vs uncoupled). Command line: ResSimCLI X.DATA --geocouple sxx,syy[,E_GPa,nu,friction,layer] (MPa, compression −). Limits: lagged by one report step, fracture-face pressure only (no poroelastic stress in the rock), black-oil.

Rate-and-state fault: earthquake cycles and induced events (C23, G3). In the left panel, Rate-and-state fault: a straight fault with a velocity-weakening patch (a < b) between creeping ends (a > b), quasi-dynamic (radiation damping), aging law. Initial stresses are Uniform (length, normal stress, pore pressure) or From the contact solve (σ_n and τ along the chosen fracture — press Solve first). Pore pressure: none, an Injection well (line source: distance, pressure scale qμ/4πkh, diffusivity, shut-in time) or the Last coupled flow run (G1-c). Run fault → tab Rate-and-state fault (G3): maximum slip rate and event magnitudes vs time, a space-time slip-rate map and the event catalogue (start, duration, Mw, slip, rupture length, stress drop, hypocentre). The status line shows the nucleation length h* and the cohesive zone Lb: keep Lb / element ≥ 3 (a warning appears otherwise). Example: defaults → periodic Mw ≈ 4.4 events every ~5 years; add an injection well 50 m from the patch centre → the next event comes years earlier. Accuracy (built-in -c23): spring-slider stability limit k/k_c, steady sliding to 6e-6, time-step independence 0.03 %.

Phase-field fracture (C23, G4, experimental). Phase-field fracture in the left panel: a pressurised crack of half-length a in an elastic plate (E, ν, toughness Gc), element size h (the band width l = 2h). Run phase field ramps the pressure to 1.3 × the Griffith pressure. Tab Phase-field crack (G4): crack volume vs pressure with the Sneddon line and the Griffith pressure, half-length vs pressure (the jump = unstable growth), and the phase-field map (0 = broken) at the critical pressure or at the end. No crack path is prescribed — this is the model to use when the path is unknown (near-wellbore, lab samples). Accuracy is controlled by l / a: at l/a = 0.1 the volume is ~40 % high and the critical pressure ~5–10 % low; both converge to Sneddon / Griffith as h is halved (extrapolated 0.96 / 0.975). Use h ≤ a/20 for numbers, a/10 for a quick look. Limits: 2-D, horizontal initial crack, pressure-controlled (the run stops when the crack jumps), no fluid flow inside the crack.

Next steps of the deep-geomechanics plan: 3-D embedded fractures (G1b, C24), DDM/ILSA hydraulic fractures (G2), rate-and-state injection design (research H7).

Continuous fracture tip, HFGROW … SUBGRID (C21, research option). Add the word SUBGRID at the end of an HFGROW record (or tick Sub-grid tip in the growth editor) and the fracture length grows continuously instead of one grid column at a time; the toughness criterion is solved inside every time step (K_I within ~4 % of K_IC). It is 10–30× slower. Research finding: on coarse grids it is not more accurate than the default — the default scheme reaches a given length too early and SUBGRID too late, both converging to the same answer as the grid is refined. Running both gives an upper/lower bracket of the grid-converged growth time.

7.7 P3D height growth (C20) — Hydraulic fractures → designer → Sizing model P3D

PKN assumes the height stays equal to the pay zone. P3D lets every cross-section grow up and down until the stress intensity at both vertical tips equals the toughness, given the stress contrast Δσ of the bounding layers. Inputs: Δσ (MPa) and a height cap. Outputs: the length, the height at the well and the profile plot (height and width along the fracture). A warning appears when the net pressure approaches Δσ (height runaway: the barrier no longer contains the fracture). With a very large Δσ the result equals PKN.

7b. Uncertainty, tracers, geostatistics, production analysis, MPI and phase field in the run (C28)

The remaining items of the CMG / TOUGH3 comparison (COMPARISON_CMG_TOUGH3.md §4) and the open HPC / geomechanics items.

  • Prediction uncertainty and data worth (FOSM, iTOUGH2 style) — Studies → History matching → Inversion statistics → Prediction uncertainty (FOSM) and data worth. Add predictions (any summary vector at a time, e.g. FOPT at the end of the forecast) to the HM study. After the match the prediction gets a standard deviation from the parameter covariance: σ_z² = g C_p gᵀ (g = dz/dp from the same runs, so no extra simulations), and a linearised 95 % interval. The data worth table shows how much each prediction's σ grows when one observed data set is removed (+44 % for the injector BHP in the test case) and how much it shrinks when a candidate data set is added (e.g. a GOR series −44 %). Use it to decide which measurement to pay for. Linear (first-order) analysis: check against a few Monte-Carlo runs when the parameters are far from linear.
  • Tracers: partitioning, dispersion, decay chains — Advanced keywords → Tracers columns K (partition coefficient into the partner phase: water tracer → oil, gas tracer → oil), parent (Bateman chain: the decay of the parent produces this tracer), alphaL (longitudinal dispersivity) and Dm (molecular diffusion, length²/day). Deck: -- RESSIM: TRACERPROP name halfLife kd [init] [K] [parent|1*] [alphaL] [Dm]. Partitioning-tracer test (PITT): inject a conservative and a partitioning tracer together; the delay of the second gives the residual oil saturation S_or = (t_p/t_w − 1)/(t_p/t_w − 1 + K). The test case recovers S_or 0.2013 for a true 0.2. Decay chains are exact for any step (integrating factor), mass balance 1e-8.
  • Kriging / sequential Gaussian simulation — Grid & rock → Kriging / sequential Gaussian simulation (conditioned to wells). Hard data are the current values in the completed cells of all wells. Choose the property (PORO, PERMX as log10 k with PERMY = PERMX and PERMZ = kv/kh·PERMX, NTG), the method (ordinary kriging = smooth best estimate; SGS = one realisation with the variogram's variability, normal-score transform, seed) and the variogram (spherical, exponential, Gaussian; ranges along / across the azimuth, vertical range, nugget). Compare it with the experimental variogram of the current property before applying. Use different SGS seeds as an uncertainty parameter in a study.
  • Gaussian-process proxy — Studies → Proxy / optimisation → Proxy model = Gaussian process (kriging / ML). This is the CMOST-style ML proxy. It interpolates the training runs, takes ARD length scales from maximum likelihood and gives a prediction band. It is better than the quadratic response surface for non-polynomial responses (leave-one-out Q² 1.00 vs 0.96 in the test).
  • Production analysis — Results → Production analysis (black-oil runs):
  • Decline curves: Arps fit (exponential / hyperbolic / harmonic) of a well or field rate from the peak, forecast, EUR to the economic limit, and remaining reserves.
  • Nodal analysis: composite Vogel IPR from the run (J above the bubble point), and the VLP of a tubing (ID, roughness, depth, THP) from hydrostatic and Darcy–Weisbach friction on the case PVT. The operating point is where the two curves intersect.
  • Create VFPPROD: writes a VFPPROD table from the same tubing model into the case being edited (rates × THP × water cut × GOR). The table is exact at the nodes.
  • Fault slip in EGS and CO2 runs — FAULTSLIP / FAULTMECH now also work with the thermal engine (thermo-elastic cooling stress: cooling unclamps the fault) and with the compositional / CO2 engine together with the FE geomechanics. This applies in the GUI, in ResSimCLI and in studies / MPI batch runs (KPIs: slip, Mw, expected events, uplift).
  • MPI distributed assembly — Run → Simulation engine settings → HPC → MPI domain decomposition → Assembly = Distributed (C28), or mpiexec -n N ResSimCLI deck.DATA --mpi-da. Every rank evaluates the properties and assembles the Jacobian rows of its own cell slab. The Newton state is replicated, and the convergence norms and well decisions are reduced over the ranks, so the results are identical on every rank and equal to the serial run. SPE9 (9,000 cells) on 2 ranks: 5.8 s vs 7.3 s with rank-0 assembly (--mpi-dd) and 7.5 s serial. Memory is still replicated per rank.
  • Level-ordered ILU(0) — for large models (≥ 20,000 cells, ≥ 128 rows per level, several threads) the block ILU(0) is renumbered by its forward levels and stored contiguously. The parallel apply then streams through memory, and the factor is bitwise equal to the serial one. Override: environment variable RESSIM_LEVEL_ILU = 2 (always), 1 or 0 (off). On 2 cores the gain is small (2.09 ms vs 2.18 ms per apply on 54k cells); it is meant for 4+ cores.
  • Phase-field fracture growth inside the run — Hydraulic fractures → Fracture growth during the run → column phase field (0/1), plus PF efficiency η, PF element h, PF E, PF ν. Deck: HFGROW name kic sigma sigmaGrad initLen closedMult PHASEFIELD [eta [h_m [E_GPa nu]]]. A persistent 2-D plane-strain phase-field model of the fracture plane (AT2, volume control, irreversible damage, G_c = K_IC²/E′) is advanced at the end of every report step:
  • Its crack volume per height is V = η × (water injected by the wells completed in the fracture's cells) / fracture height.
  • Its half-length opens the EDFM pieces of both wings.
  • It replaces the LEFM piece test for that fracture.

Choose η, the fluid efficiency (stored crack volume / injected volume). Use 0.05–0.6 for fracturing treatments, and much less for slow water injection (the test uses 0.002 for 2 m³/d). The phase-field pressure is shown next to the flow-model fracture pressure in Results → Faults & seismicity → Fracture growth (phase field). The coupling is one-way by volume, so the two pressures differ when η does not match the leak-off of the flow model. Verification: the half-length is within 10 % of the toughness-regime Griffith–Sneddon length a = (E′V/(2√π K_IC))^{2/3} (32.1 m vs 35.5 m). The model runs in a worker thread and costs a few seconds per report step on a 2-D mesh with h ≈ L_max/60. It is not part of restart files: after a restart it starts again from the initial crack and keeps the pieces that are already open. * Sub-grid leak-off — Hydraulic fractures → Fracture growth during the run → column sub-grid leak-off (0/1), used together with sub-grid tip = 1. Deck: HFGROW … SUBGRID LEAK. A fresh host cell at the tip no longer leaks off as if the whole cell were exposed, so the growth time is almost grid-independent. In research Cycle 7, 10 m cells gave the 2.5 m answer within 3 % (C29 engine: t60 25.3 / 25.6 / 26.0 d vs 28.7 / 27.4 / 26.8 d without; on a dipping corner-point grid 23.0 / 22.8 / 23.7 vs 25.8 / 24.5 / 24.0 d — research Cycle 8, F24). It also runs faster (fewer cuts). Recommended whenever SUBGRID is used.

7c. Salt precipitation, wellbore friction / ICDs, surface network, two-way phase field and GPU CPR-AMG (C29)

These are the items still open after C28 (COMPARISON_CMG_TOUGH3.md §4). All of them are in the ResSim engine and have panels on the Advanced keywords page (or the hydraulic-fracture / HPC pages). The ENGINES_AND_MATH.md §6.22 section has the equations and verification numbers.

  • Salt precipitation and dry-out (TOUGH3 EWASG type): Advanced keywords → Salt precipitation and dry-out. Tick On, then give the initial NaCl concentration of the water c0 (kg/m³ water), the solubility (default 317), the halite density (2165), the Verma–Pruess parameters φ_r (fraction of porosity at which permeability vanishes, 0.8) and Γ (0.8), the temperature (°C, for the vapour capacity of the gas) and the concentration of the injected water. Deck: -- RESSIM: SALT c0 [cSol [rhoSalt [phiR [Gamma [T_C [cInj]]]]]].
  • What it does. Dry gas that flows through brine-bearing cells takes up water vapour. The brine left behind concentrates, and above the solubility halite precipitates. This lowers porosity and permeability (tubes-in-series model). Injected fresh water dissolves the salt again.
  • Results. 3D property SSALT (solid salt, fraction of pore volume), KSALT (permeability factor; choose Engine output array → KSALT), and the injector BHP. Typical uses are CO2 or gas injection into saline aquifers and gas storage near-well dry-out.
  • Limitations. Halite only. The vapour does not condense again. Two-way geomechanics permeability coupling of the same cells overrides the salt factor.
  • Wellbore friction and inflow-control devices (FlexWell-lite): Advanced keywords → Wellbore friction and ICD. Each well gets one row. On adds the well. Then enter the tubing inner diameter (ft or m), the roughness and, if wanted, the ICD strength K (Δp = K·ρ_mix/ρ_cal·q² per connection, q in reservoir rate) with its calibration density ρ_cal. Deck: -- RESSIM: WELLBORE well ID rough [icdK [rhoCal]].
  • Connection order. The connections are taken in COMPDAT order, heel first. Friction accumulates toward the toe, so a long horizontal well no longer drains evenly. ICDs restore an even inflow and delay gas / water coning at the heel.
  • Results. Custom-plot well vector WDPWB (wellbore + ICD drop at the deepest connection), WOPR / WGOR per well.
  • Limitations. No wellbore storage, no slip / hold-up and no annulus flow (full FlexWell / multi-segment wells remain OPM Flow / ECLIPSE features: WELSEGS decks are kept and run there).
  • Surface network (ECLIPSE extended network): Advanced keywords → Surface network.
  • Panel. It counts the NODEPROP / BRANPROP / VFPPROD tables in the deck and edits the terminal pressure and the branch VFP numbers. + Create network writes a terminal node FIELD at the given pressure and one branch per producer group. A warning appears when a branch refers to a VFP table that does not exist.
  • Engine. The network is balanced every time step: node pressures come top-down from the terminal node through the branch VFP tables. Each producer then gets its node pressure as a THP limit, which its own tubing table (WCONPROD item 11) turns into a BHP limit.
  • Results. Custom-plot well vector WTHPN (the node pressure each producer sees as its THP limit), WBHP, and the run log line Surface network. OPM Flow runs the same keywords (add NETWORK to RUNSPEC).
  • Limitations. One explicit balance per step, and no automatic chokes / compressors.
  • Two-way phase-field coupling: Grid & rock → Hydraulic fractures → Fracture growth during the run → column "PF two-way (0/1)". Deck: HFGROW … PHASEFIELD eta … TWOWAY. After the first phase-field step the crack volume follows the flow model's fracture pressure (V = compliance × net pressure, capped by the injected volume of the step) instead of the fixed efficiency η. The phase-field and flow pressures therefore agree (34.11 vs 34.18 MPa in HFGROW_PF_TWOWAY.DATA). Growth starts only when the flow pressure exceeds the closure stress, so at low rates the crack may not grow at all.
  • CPR-AMG on the GPU: HPC → GPU linear solver → Preconditioner = CPR-AMG (device V-cycle, C29). The pressure AMG hierarchy is built on the host and the V-cycle runs on the D3D11 compute device, followed by the block-ILU(0) stage. In the test it needs 23 iterations against 43 for multicolour BILU0. Use it for large, strongly heterogeneous models; keep MC-BILU0 for small ones.
  • Not done: dynamic gridding (CMG DynaGrid). Adaptive coarsening / refinement during the run is deferred. It needs remapping of every state array (incl. tracers, salt, geomechanics) and of restart files. Use static LGR (CARFIN) around the front instead. The design note is in ROADMAP.md (C29).

New examples: SALT_DRYOUT.DATA, WELLBORE_ICD.DATA, NETWORK.DATA and HFGROW_PF_TWOWAY.DATA (see §8).

7e. Run-time logic: UDQ, UDA and ACTIONX in the ResSim engine; well section view (C31)

ECLIPSE / OPM decks often contain run-time logic: quantities computed during the run (UDQ), well targets taken from those quantities (UDA), and rules such as "shut a producer when its water cut passes 80 %" (ACTIONX). Before C31 ResSim kept these keywords for OPM Flow but ignored them, so the results differed. The ResSim engine now evaluates them, and the deck text is unchanged, so ResSim, OPM Flow and ECLIPSE run the same logic.

Writing the logic: Model → Schedule → Run-time logic: UDQ, UDA, ACTIONX. * The list. Shows every UDQ block and ACTIONX at its report step, with a live check (OK, or the parse error). * New UDQ block / New ACTIONX / From a template... Templates: * field water cut + voidage replacement ratio; * well liquid rate + average producer BHP; * injection target = produced reservoir volume; * shut producers above 90 % water cut; * shut producers with a high GOR; * cut rates when the field pressure falls; * change controls from a calendar date. * UDQ form. One row per record (DEFINE / ASSIGN / UPDATE / UNITS) with name and expression. The Check column parses the expression while you type. * Names start with FU (field), WU (per well) or GU (per group). * Expressions can use summary quantities (FOPR, FWPR, FVPR, FPR, WWCT 'P*', WBHP, GOPR 'G1' …), other UDQs, TIME / DAY / MNTH / YEAR, + − × / ^, comparisons, ABS EXP LN LOG SQRT NINT, and the set functions SUM AVEA MAX MIN …. * ACTIONX form. Name, maximum number of runs and minimum inerval. Condition ws eft de – operator – right side – AND / OR. * he body: the keywords to apply. Use '?' for "the wells that triggered the condition". * Deck text. Shows the same block as ECLIPSE text, for anything the form cannot show (parentheses, comments). * UDA. Pick a report step, a well control, a target (ORAT, WRAT, GRAT, LRAT, RESV, BHP, THP for producers; RATE, RESV, BHP, THP for injectors) and a UDQ, then press Attach. On export the deck gets 'FUINJ' in that item. In an imported deck the UDA items are recognised automatically.

How the engine evaluates it. * UDQs are re-computed after every time step. * A UDA target follows its UDQ from the next time step on. If the value is undefined, the previous target stays. * ACTIONX conditions are checked at the end of every report step, as in OPM Flow. When true, the body applies from the next report step, until the maximum number of runs is used up. * Restart continues identically: UDQ values, run counts and the applied action bodies are saved. * Limits. An action cannot add new connections during the run (ResSim warns). PYACTION is not evaluated.

Seeing it: Results → UDQ & actions. * Every UDQ vector of the run plotted against time, with filter and log scale. * Red markers at the times the actions fired. * A table of the firings: time, report step, action, and the wells that '?' stood for. * The Deck logic tree shows how the engine understood each UDQ and action. * UDQ vectors (FUWCT, WU…:well) are also written to the ECLIPSE summary file of the run, so the result viewer and other tools see them.

Well section: Results → Fields & sections → Well section. * The curtain. A vertical slice of the grid that follows the well's trajectory, coloured by any array at any report step. A horizontal or deviated well gets a curtain along its path; a vertical well gets an east–west slice. Margin extends the curtain beyond the ends. * Overlays. The trajectory and the connections are drawn on top: green = open producer connection, blue = open injector connection, grey = shut. * Hover shows the cell and its value. The colour range modes are the same as in the Section map. * Log tracks. Up to 4 narrow plots beside the curtain, like a well log. Each shows an array (default PRESSURE, SWAT, SOIL) in the connection cells against TVD or MD. The dashed grey line is the first report step, so you see directly how the well's layers depleted or watered out.

New example: ACTIONX_UDQ.DATA. A waterflood with four producers: * injection = 1.05 × produced voidage + 500 stb/d (UDA); * a producer rate limit as a UDQ; * producers shut at 80 % water cut (P1 at 870 d, then P2–P4 together at 1110 d); * a higher rate limit once the field pressure exceeds 5300 psi (330 d).

Open Results → UDQ & actions after the run.

7j. Gas-lift optimisation (C35)

The ResSim engine allocates lift gas to THP-controlled producers. Lift gas lightens the fluid column in the tubing, so a well that cannot flow, or flows weakly, against its THP limit produces more. The allocation is optimised at every time step.

Requirements. Each producer needs: * a THP limit (WCONPROD item 10); * a VFPPROD table (item 11) with an ALQ axis, the lift gas rate (type GRAT or blank).

The Producers ready for gas lift line shows which wells qualify.

Set up (Wells → Gas-lift optimisation (LIFTOPT / WLIFTOPT / GLIFTOPT)): 1. Switch gas-lift optimisation on. This adds LIFTOPT, with an increment of 1/10 of the largest table ALQ, and WLIFTOPT YES for every producer. 2. LIFTOPT: * the increment: lift gas is handed out in these blocks; 0 switches the optimisation off; * the minimum economic gradient: the extra oil per unit of extra lift gas below which no more gas is given; * the minimum interval between optimisations. * Add rows with later steps to change the settings during the run. 3. WLIFTOPT, per well or pattern (OP*): * Optimise YES/NO; NO with a maximum fixes the rate (NO 0.0 = lift gas off for that period); * the maximum lift gas rate (default: the largest ALQ of the table); * a weight that gives priority to some wells; * the minimum rate (negative = just enough to flow); * the weight on the extra produced gas. 4. GLIFTOPT: limit the lift gas supply of a group (compressor capacity), or its total gas (produced + lift). GCONPROD targets are also respected: lift gas that would only produce oil above a group target is not used.

Results. * The section plots FGLIR and every well's WGLIR of the last run (stairs: each value is the rate over the preceding step). * All lift gas vectors are in Results → custom plots: FGLIR / FGLIT, WGLIR / WGLIT. The solvent vectors FNIR…FNIP and WNIR / WNPR are now listed there too. * They are written to the ECLIPSE summary files.

Example decks (decks/gaslift, opm-tests, see its README): * GASLIFT-01: six wells that only flow with lift gas, with lift gas switched off for two months, an economic gradient, well weights and a platform lift gas limit. * GASLIFT-04: a three-phase model whose FOPT and FGPT match the commercial simulator within 0.3 %.

Restart. Gas lift state is saved. A restart of a THP case now continues the run exactly; earlier versions recomputed the THP-derived BHP limit after a restart.

Limits. * The ALQ types IGLR / TGLR are converted from the lift gas rate. Other ALQ types (e.g. pump power) need WLIFTOPT item 3 and are not optimised against gas. * LIFTOPT item 4 is ignored: the allocation is per time step. * GLIFTLIM and the MSW / network gas-lift decks GASLIFT-05…15 are kept verbatim for OPM Flow / ECLIPSE. * The method is in ENGINES_AND_MATH §6.30.

7k. Surface network and facilities (C35)

The ResSim engine balances surface networks the way OPM Flow does. The editor is under Advanced → Surface network & facilities.

Building a network * Extended network: NODEPROP gives node pressures; BRANPROP gives the branches (child, parent, VFP table, ALQ). * VFP table 9999 = a flow line with no pressure loss. * VFP table 0 = remove the branch (use it in a later step to take a branch out). * Create network writes 9999 when no VFP table is chosen. * Standard network: GRUPNET on the group tree. A terminal pressure makes a fixed-pressure node; a VFP table makes a branch to the group's parent. When GRUPTREE moves a group later, its branch moves with it (re-routing). * NEFAC scales the flow a node passes upstream.

Facilities (quick-add row in the same panel): * GSATPROD: a satellite field with fixed oil / water / gas rates (and lift gas). No wells; it adds to the field rates and flows through its network node. * GCONSUMP: fuel consumption and gas import of a group. They reduce the gas left for re-injection and sales, but not FGPR. Item 4 names the network node; 'NO-NODES' keeps the consumption out of the network. * GCONSALE: a gas sales target. Gas re-injection (GCONINJE REIN) is reduced so the target is sold first. * Automatic choke: NODEPROP item 3 = YES on the node of a group with a GCONPROD target. The engine raises the node pressure until the group meets its target. If the network cannot deliver the target, the choke stays open.

7n. Wellbore flash, slip, storage, flow limits, pumps and Python actions (C37)

Model → Wells → Multisegment well (generator): * Tubing flash (on by default): dissolved gas comes out of solution as the pressure falls up the tubing, so the column gets lighter and the gas is shown where it really is. Switch it off to get the old behaviour (all phases kept at the reservoir split). * Segment storage (on by default): each segment keeps its fluid between time steps, and new fluid mixes in with the volume that flows through. After a shut-in the column stays as it was. WELSEGS item 11 (segment volume) is used if given. * Oil–water slip (drift-flux wells): factor, A, B1, B2, N. These are written as WSEGDFPA items 7–11, so oil overtakes water in upward flow. * Flow limit (WSEGFLIM): phase (OIL / WAT / GAS / LIQ), limit and sharpness for the segment. The inflow of that phase is held near the limit while the well is on its BHP limit. * Downhole pump (WSEGPULL): boost DP, on-factor P, and the oil rate Qo above which the boost decays with gradient G.

Both options are stored as -- RESSIM: MSWOPTS flash storage (1 / 0), so OPM Flow and ECLIPSE ignore them. A third value switches on the experimental multisegment cross-flow (C45, section 7w).

WSEGFLIM and WSEGPULL follow ResSim's documented assumptions (ENGINES_AND_MATH §6.36), because the ECLIPSE description was not available. OPM Flow reads both keywords but does not simulate them.

Results → Multisegment wells: * counts of FLIM / PUMP segments, and the status of slip / flash / storage; * the oil fraction of the liquid on the right axis; * pump boost as stems; * new table columns: oil / liquid, head density, pump boost, limiter factor and local rate.

Model → Schedule → Run-time logic → PYACTION: * Python interpreter: a path to python.exe. Leave it empty to use python on the PATH. Test shows the version. * New PYACTION from a template: * a well controller (opens wells one by one when FOPR drops); * water-cut shut-in; * a rate cut on cumulative oil (insert_keywords); * the legacy run() form with the ACTIONX callback.

The script file is created next to the deck. * Each record has a name, a run count (SINGLE / UNLIMITED / FIRST_TRUE), a script file (relative to the deck folder) and the step it starts from. * The script editor has Save, Reload, Check syntax (compiled by the configured Python) and Replace with a template.

The ResSim engine calls every script at the end of each report step. Scripts read summary values and change the schedule:

7o. Well cycling (WCYCLE), grid units (GRIDUNIT), large models (C37)

  • WCYCLE. Type it in the SCHEDULE editor; a snippet and tooltip are included.
  • Example: 'P1' 20 40 3 1 'YES' / keeps P1 open for 20 days and shut for 40 days.
  • After every re-opening, the rate ramps up linearly over 3 days, and the first step is at most 1 day.
  • YES makes the time steps land exactly on the switch times.
  • WELOPEN OPEN restarts the open period, and so does a successful WTEST.
  • The switches are written to the run log (WCYCLE opens / shuts well …).
  • The well's rate curve in the Results plots shows the cycles.
  • WTEST with reason P. A well that cannot flow at its BHP limit is shut and re-tested every interval. One example is an injector whose BHP limit is below the reservoir pressure.
  • GRIDUNIT. Grids exported in centimetres or feet (GRIDUNIT 'CM' /) are converted on import. The 3-D view and the volumes are therefore correct, and exporting writes the converted geometry.
  • Large models. Generate a test model with python tools/gen_bigcase.py 100 100 10 big.DATA, which has 100 k cells.
  • Expect about 4 kB of RAM per cell, so 1 M cells needs about 4 GB.
  • Use all cores: Settings → Threads 0.
  • -- RESSIM: TUNING 0.3 0 2 1 1 switches on the float32 ILU(0) factors (since C38 level-parallel: 12 % faster on 100 k cells, see 7p).

Steps replay palette commands by their exact label, so a workflow recorded in one version keeps working as long as the command names stay the same; an unknown label stops the run with a message.

Fault network (Geomodel › Faults). The Fault network (junctions, truncation, throw QC) panel works on the interpreted fault sticks. Detect junctions finds X crossings and Y junctions – a minor fault whose tip ends within the snap tolerance (plan distance; 0 = two cells) of another fault – and lists them with depth and the faults involved. Apply truncation cuts the minor fault at the major one on nine depth levels, adds a terminal stick on the major trace and removes the sticks beyond it, so the pillar grid gets clean fault blocks. The throw profile table shows the throw along each fault (hanging wall on the dip side, throw = z(HW) − z(FW); reverse segments are flagged when they exceed 5 % of the maximum, and the throw can taper to zero at the tips). Revert restores the faults as interpreted. After a change the status line asks you to rebuild the 3-D grid.

Facies by truncated Gaussian simulation (Model › Grid properties › Geostatistics). Facies (truncated Gaussian simulation) simulates one Gaussian field with the variogram of the panel and cuts it at the thresholds of the cumulative target proportions (facies are ordered: 1 touches 2, 2 touches 3, …). Every cell then gets the porosity and permeability of its facies (PERMY = PERMX, PERMZ = kv/kh × PERMX; a negative value keeps the current property) and, with Set SATNUM = facies, its own SWOF / SGOF table. Facies codes at wells condition the field. The recipe is stored in the deck as -- RESSIM: PROPFAC … together with the PROPMODEL recipe, and Send to Model in the Geomodel stores the facies recipe in the same way. In Studies, the geomodel parameters range multiplier (GeoRange) and realisation (GeoSeed) now re-simulate the facies too, so sensitivity, ensembles and history matching can vary the facies architecture. Note: the base case keeps the full heterogeneity of the original model; a re-simulated realisation has the facies-scale contrast only (one porosity / permeability per facies).

Inspector: show only modified. The Inspector toolbar has show only modified (next to the filter, Ctrl+F). Rows whose value differs from the baseline get a marker; with the option on, unmodified rows are hidden. The baseline is taken when a project is opened, created or imported; right-click the show only modified toggle to take the current values as the new baseline. Limitations: a value that was changed outside the Inspector (deck editor, scripts) before its row was first drawn becomes part of the baseline, and a table that is re-allocated (rows added or removed) loses its markers.

Languages. View › Language switches the interface language at once (saved in the settings). Spanish is included; the main menus, the toolbar and the workspace switcher are translated, everything else stays in English. Catalogues are plain text files lang/<code>.txt next to the executable (# LANGUAGE es Español, then English text<TAB>translation per line; \n and \t escapes, # comments, an empty translation keeps the English text). To add a language, copy es.txt, translate the right-hand column and restart. Developers mark strings with TR("…") (translated) or TRN("…") (static tables, translated where drawn) and run python3 tools/i18n_extract.py --update lang/<code>.txt to add new strings and list unused ones. Design tokens. Section headers are now card title bars (raised surface, accent stripe, bold text); buttons have three roles – primary (accent fill: Run, Apply), secondary (accent outline: Open, Save) and danger (red: Clear, Delete, also in the light theme); spacing, corner radius (6 px) and surface levels follow one scale in every theme.

Engine (C41). Injector cross-flow: a water or gas injector completed across layers with different pressures now produces from the connections whose cell pressure exceeds the wellbore pressure and re-injects through the others (WELSPECS item 10, default YES; the rate target counts the net injected phase) – as in OPM Flow and ECLIPSE. Multisegment wells do not cross-flow yet. Producer cross-flow (wellbore mixture into low-pressure layers) was added earlier in C41. CECON: connection economic limits (water cut, GOR, WGR per completion or COMPLUMP lump; CON, +CON and WELL workovers; stopped wells checked only with item 10 = YES; C42 added the minimum-rate items and PLUG, see §7t). Vector Meaning
WPWE0 Drilled from a drilling queue. Always 0: ResSim has no QDRILL / WDRILTIM.
WPWE1 Connections opened in this step, counted only while the well is open.
WPWE2 Connections closed. Connections closed only by the reach of a '+CON' workover are not counted; only the offender is.
WPWE3 1 when the well is closed to bottom: a '+CON' reach past the offender, or this step's closures leave the well flowing only over its topmost completion, or not at all.

WPWE5 / WPWE6 1 when the well changed from injector to producer / from producer to injector.

7w. Large models in less memory, translated panels, multisegment cross-flow option (C45)

Less memory on large models. The engine no longer keeps a scalar copy of the Jacobian next to the block matrix. Peak memory falls by about a fifth, and results are identical (100 k cells: 416 → 322 MB). Solver → Low-memory linear solver also stores the ILU(0) factors directly in single precision (100 k cells: 294 MB). Its settings are: * Auto (default): on from 500 000 active cells. * Off or On.

A double-precision factorisation takes over automatically if a solve stalls. A 1-million-cell black-oil model needs about 2.8 GB. In a deck the option is -- RESSIM: TUNING item 10 (−1 auto, 0 off, 1 on), or the fourth token of the SOLVER line in a .rsim file. RESSIM_LEAN=0|1 overrides it for one run.

Translated panels. View › Language now also translates the Model and Results panels, the property inspector, tables and most help tooltips (about 2 000 texts in lang/es.txt). Panel layouts and selections are kept when the language changes. These stay English: popup titles, plot legends and axis units, keyword and vector names, and the built-in keyword documentation.

Multisegment wells – cross-flow (experimental, off). A cross-flowing connection of a multisegment producer can re-inject the fluid of its own tubing segment, as in OPM Flow. Turn it on with -- RESSIM: MSWOPTS 1 1 1 (third value) or the environment variable RESSIM_MSW_XFLOW=1.

It is off by default. With ResSim's step-lagged segment heads it can oscillate: on the OPM test MSW-2D-VERT-02 the gas–oil ratio error rises from 3.6 % to 24 %. Without it, back-flowing MSW connections are shut for the step (the C44 behaviour). Standard wells cross-flow as before (WELSPECS item 10).

7y. Gas tables at low pressure, fault history files, reading regression results (C47)

Gas PVT tables at low pressure. A PVDG or PVTG table usually starts well above atmospheric pressure. Extrapolating it down to about 1 bar can give a negative gas formation volume factor. This matters, for example, for well potentials at a 1 atm BHP. ResSim now adds the same low-pressure rows as OPM Flow, at 1 bar and at the pressure where B reaches 10 × its first value (at least 1). Nothing has to be changed in the deck. Results above the first table pressure are unchanged.

Fault history file. Every coupled fault run (FAULTMECH / STRESSFIELD) can write the per-face history to a CSV file:

ResSimCLI CASE.DATA --fault-csv faults.csv        (or set RESSIM_FAULT_CSV=faults.csv)

There is one row per report step and fault face: t, face, fault, k, x, y, depth, area, aSig, cff, dcfs, rate, cum. * t is in days; k is the layer, counted from 1. * cff / dcfs are the Coulomb stress and its change; rate is the seismicity rate relative to background; cum is the cumulative expected number of events. * Stresses and coordinates are in the deck units.

The file opens directly in Excel or Python for custom plots and statistics.

ACTIONX fixes. * A well whose connections are all added by an ACTIONX block, with the WELSPECS reference depth left at its default, now gets the correct reference depth. Before C47 such injectors stopped the run. * The month JLY is accepted in ACTIONX conditions, for example MNTH >= JLY.

CO2STORE decks import without the old "not modelled" warning: they run on the compositional CO2STORE engine.

Reading deck-regression results against OPM. OPM regenerates its reference results with every change to OPM Flow. Some references move by more than the 5 % tolerance between OPM versions: * NETWORK-01-WTEST, T1L, UDQ_WCONPROD, UDQ_ACTIONX and 9_3A are moving targets. A FAIL on these cases may only mean that the reference was produced by a different OPM version. On T1L, ResSim passes the 2025-05 reference (3.2 %). * 9_3A has a transient near day 136–151 that OPM's own versions place differently (45 % apart in FWCT). * On stable references (6_ENDSCALE, 9_1A, 0A1, 0B_WELPI, ACTIONX_M1, 7_HYSTERESIS, WSEGSICD / AICD), a FAIL points to a real difference.

tools/dev/smrydiff.py A.SMSPEC B.SMSPEC compares two summary files aligned in time and lists the vectors that differ most.

7za. Converged multisegment-well heads, fault ramp, translated window titles (C49)

Multisegment wells are more stable. The pressure difference between the top of a multisegment well and each connection (the "head") now depends on the fluid that is in the tubing at the end of each time step. ResSim repeats a step (up to 8 times) until these heads stop changing. You do not have to do anything: this is the new default. In tests it never made a result worse and improved one OPM test strongly (TEST_WSEGSICD: 93 % → 34 % difference). Multisegment runs take roughly 10 % to 2.5× longer.

To get the old behaviour (heads from the start of the step), open Model › Wells › Multisegment well and set connection heads to explicit. In a deck it is the fourth value of the ResSim option line:

-- RESSIM: MSWOPTS 1 1 0 0      (flash, storage, cross-flow off, explicit heads)

Cross-flow inside multisegment wells works now. The producer cross-flow in segments check box (third MSWOPTS value) used to make some wells flip between gas and liquid from one step to the next. With converged heads that is gone (MSW-2D-VERT-02: 23.8 % → 1.9 % difference to OPM Flow). It stays off by default because none of the OPM tests improved with it.

Fault permeability ramp. In the fault-mechanics table (Fault mechanics & induced seismicity section), the new column ramp (x sigma'n) sets how quickly a reactivated fault opens: the transmissibility factor reaches its full value when the Coulomb stress exceeds failure by this fraction of the effective normal stress (default 0.05). A larger value means a gentler, smaller change for the same stress. --fault-csv files now also contain sne (effective normal stress) and mult (the transmissibility multiplier in force).

Stopped wells show a BHP. A well with status STOP now shows the bottom-hole pressure at which it would not flow (WBHP), as OPM Flow and ECLIPSE do. A SHUT well still shows 0.

Well results of CO₂ storage and compositional runs in studies and regressions. Runs started from Studies, from the regression runner (ResSimCLI --regress) or from the C / Python API now keep the per-well rates and BHP for compositional, CO2STORE and thermal decks. Before, only field totals were kept.

Window titles are translated. With Spanish selected, window titles, docked tabs and pop-up titles are shown in Spanish too, and so is the deck editor's toolbar. Your saved window layout keeps working in every language.
